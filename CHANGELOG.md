## [Unreleased]

### Features
- **ElevenLabs voice-note replies** ([docs/VOICE-REPLIES.md](docs/VOICE-REPLIES.md#elevenlabs-provider)), off unless the owner sets `VOICE_REPLY_PROVIDER=elevenlabs` (voice replies stay off by default): Arabic replies, and any language the Workers AI model lacks, are spoken with the owner's ElevenLabs voice (`ELEVENLABS_VOICE_ID`, `ELEVENLABS_MODEL_ID` default `eleven_v4`, secret `ELEVENLABS_API_KEY`). ElevenLabs returns Ogg Opus (48 kHz, mono), uploaded and sent as a voice note through the existing path; Workers AI languages are unchanged. Cap `ELEVENLABS_MAX_CHARS` (600); every ElevenLabs error, including quota and rate limits, sends the text instead, with `voice_tts_el_*` codes and counters in `get_overview`. The key is never logged or returned and is scrubbed from MCP results.
- ElevenLabs requests carry only `text` and `model_id`, like the ElevenLabs studio (the voice's saved settings apply; no `language_code`, which pushed the voice toward standard Arabic). Arabic replies on `eleven_v3` / `eleven_v4` with the Lebanese dialect get a `[casual Beiruti Lebanese accent]` direction (`ELEVENLABS_ACCENT_TAG`, on by default); square brackets in the reply itself are removed before speaking.
- **Spoken Arabic wording** ([docs/VOICE-REPLIES.md](docs/VOICE-REPLIES.md#arabic-wording-lebanese-dialect)): while voice replies are on, `get_history` returns `voice_reply` (`expected`, `provider`, `max_chars`, `arabic_style`), and the `send_reply` description asks for Beiruti Lebanese dialect in Arabic script for spoken Arabic (`ARABIC_REPLY_DIALECT`, default `lebanese`, `none` to turn it off).

### Changed
- `scripts/hygiene-scan.sh`: ElevenLabs is no longer flagged as an out-of-scope voice provider (it is now an owner-selectable voice-reply provider); a new detector flags `sk_` style API keys, and the log/MCP shape filter redacts them.

## [0.3.0] - 2026-10-20 (preview)

Media understanding: customers' voice notes are transcribed and their images described with Workers AI in your own Cloudflare account, inside the free daily allowance, with a plain fallback marker on any failure. Optional voice-note replies, off by default (`mirror` mode recommended); no Arabic text-to-speech exists on Workers AI, so Arabic replies stay text.

### Features
- **Voice notes and images** ([docs/MEDIA.md](docs/MEDIA.md)): inbound audio is transcribed with Workers AI `@cf/openai/whisper-large-v3-turbo` (language detected, for example Arabic, French, English) and inbound images are described with `@cf/meta/llama-4-scout-17b-16e-instruct`, in the background after the webhook's 200, once per message id. The text is stored on the message (type kept) and reaches the agent through `get_history` as untrusted customer text (`[voice note, transcribed, language: ar] ...`, `[image] description: ... | caption: ...`). The agent's wake waits for the job (at most 25 s). Caps `MEDIA_MAX_AUDIO_SECONDS` (120), `MEDIA_MAX_AUDIO_BYTES` (2 MB), `MEDIA_MAX_IMAGE_BYTES` (3 MB); any failure, including the free daily allowance being used up (error 3036), gives `[voice note, not transcribed]` / `[image, not described]` with no retry. Switches `MEDIA_TRANSCRIBE`, `MEDIA_DESCRIBE` (default on). `get_overview` gains a `media` block (counters only). New `[ai]` binding in `wrangler.toml` and `scripts/cf-api-deploy.mjs`. Raw media is never stored or logged.
- Owner-only `POST /api/admin/media-selftest` (404 unless `MEDIA_SELFTEST=1`) to check the media path without a phone; `scripts/smoke.sh` checks that it is off.
- **Optional voice-note replies** ([docs/VOICE-REPLIES.md](docs/VOICE-REPLIES.md)), off by default (`VOICE_REPLIES=off|mirror|on`): `send_reply` can speak the reply with Workers AI `@cf/myshell-ai/melotts` (English, French, Spanish, Chinese, Japanese, Korean; no Arabic), encode it to Ogg Opus in a Durable Object with a bundled WebAssembly encoder (libopus, speexdsp resampler, minimp3; `scripts/build-voice-wasm.sh`), upload it to Meta and send it as a voice note. All `send_reply` guards run first, the text is always stored, any failure sends the text, counters in `get_overview`. Owner-only `POST /api/admin/voice-selftest` (404 unless `MEDIA_SELFTEST=1`); `scripts/smoke.sh` checks that it is off.

### Changed
- `scripts/hygiene-scan.sh` (out-of-scope voice provider check) allows exactly the Workers AI model id `@cf/openai/whisper...`, which runs in your own Cloudflare account; every other mention is still flagged.
- Worker bundle grows to about 730 KiB (274 KiB gzipped) with the voice-note encoder.

## [0.2.0] - 2026-10-19 (preview)

### Features
- **Bot-started messages:** new agent MCP tool `start_conversation` (no lease; `idempotency_key` required) for reminders the customer asked for and follow-ups on an open case, never marketing. It is refused with no Meta call when the number never wrote in (unless the owner put it on `OUTREACH_ALLOWLIST`), when the conversation is in human takeover, held, escalated or active (`conversation_active_use_send_reply`), after an opt-out, while auto-reply is paused, in test mode for numbers outside `TEST_RECIPIENTS`, for a non-allowlisted template, outside the 24-hour window for text, and by the same rate limits as `send_reply`. Every guard is re-checked inside the one atomic reserve commit. Owner batches: `POST /api/admin/start-conversation` runs the same function. New settings `WA_WABA_ID`, `WA_APP_ID`, `OUTREACH_ALLOWLIST`.
- `send_reply`, `start_conversation` and staff replies share one delivery function (`deliver`): one Meta POST, then sent / failed / uncertain (held for review), with the same idempotency rules.
- **Opt-out:** STOP, UNSUBSCRIBE, ARRET, ARRÊT or إيقاف (the whole message) marks the conversation opted out; START clears it. The message is still stored and still wakes the agent. Shown as `opted_out` in `get_history`, `get_controls`, the inbox and the admin conversation view; `get_overview` counts opted-out conversations. Staff actions `opt_out` / `opt_in`.
- **Team inbox** at `/admin` replaces the staff table: conversation list and chat bubbles side by side (one pane at a time on a phone), a "Needs a human" queue, unread counts, search, a reply box (text inside the 24-hour window or an allowlisted template; replying takes the chat over from the bot), take over / release to the bot / resolve / release hold / wake / opt-out / erase, and a 10-second refresh while the tab is visible.
- **Staff sign-in without the admin token:** `POST /api/admin {"action":"staff_invite"}` (owner token only) returns a one-time code (single use, 15 minutes by default, only its hash stored). `/admin` redeems it for an HttpOnly, Secure, SameSite=Strict session cookie (12 hours, signed with `ADMIN_TOKEN`). Changing requests with the cookie need `X-Staff-Request: 1`; a staff session cannot mint invites, start conversations or read secrets.
- Meta setup `subscribed_apps` step: facts now list `before_app_ids` and `after_app_ids` (ids only), plus a WARN when other apps were subscribed but not yours. The admin MCP `setup_check` reads the WABA's subscribed apps (GET only) when `WA_WABA_ID` is set.
- Meta setup `store_token: true` (with `mint_token`): the verified system-user token is written into the Worker's own secret store and never returned; falls back to the one-time delivery if storing fails.
- `GET /api/health` liveness endpoint (`{ok, version}` only, no storage read).
- New Cloudflare accounts: `scripts/cf-api-deploy.mjs` and `scripts/deploy-cloudflare.sh` (with `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`) register a workers.dev subdomain first when the account has none (`--subdomain NAME`); an existing subdomain is never changed.

### Fixes
- `scripts/deploy-cloudflare.sh` (wrangler route, `--set-secret` and `--self-provision`) now exits non-zero and names every required secret that was skipped or failed to upload (names only, never values); the final "Done" line is printed only when all of them were set.
- `scripts/smoke.sh` retries each check with backoff (2s doubling, capped at 30s) within a shared budget of about 3 minutes (`SMOKE_RETRY_SECONDS`, default 180; `0` checks once; `SMOKE_RETRY_MAX_DELAY` caps the delay), so checks right after a deploy do not fail falsely, then fails with a summary of the checks still wrong.
- Tests for both scripts against a fake wrangler and a local fake Worker (`tests/deploy-smoke-scripts.test.ts`).

- `scripts/smoke.sh` also checks `GET /api/health`.

### Documentation
- README (and all 19 translations), `docs/STATUS.md`: the setup has been proven live on 2 different accounts.
- Cloudflare API token permissions (Workers Scripts: Edit only), show-once token handling, existing accounts (list Workers first, never touch others), the workers.dev subdomain step.
- `docs/CONFIGURATION.md`: `start_conversation` guards and error codes, opt-out, team inbox and staff sign-in routes, new settings. `docs/META-SETUP.md`: subscribe-and-verify the app on the WABA, `store_token`. `docs/PRIVACY.md`: opt-out.

## [0.1.0] - 2026-10-17 (preview)

First version of the Cloudflare Workers template: one Worker and one SQLite-backed Durable Object per business. Verification status of every claim below: [docs/STATUS.md](docs/STATUS.md).

### Features
- Secret safety: every MCP tool result, JSON-RPC error and log line passes a key-shape filter (API keys, bearer tokens, webhook secrets); new tests and a stricter hygiene scan fail on key-shaped values.
- Call limits default to 120 seconds per call (`CALL_MAX_SECONDS`) and 1200 seconds per UTC month (`CALL_BUDGET_SECONDS`); both are Worker variables ([docs/VOICE-CALLS.md](docs/VOICE-CALLS.md)).
- **Name:** the product and repository are now **WAB bot** (slug `wab-bot`; was "WhatsApp Bridge Template"): package, README and all 19 translations, docs, MCP server names, default Worker name, update-check agent. README tagline: AI auto-reply and voice answering for business chat on the WhatsApp Cloud API. Where to change it again: [docs/RENAMING.md](docs/RENAMING.md). The non-affiliation notice (not affiliated with or endorsed by Meta/WhatsApp or xAI) stays everywhere. The Durable Object class names are unchanged.
- Webhook receiver with HMAC verification over the raw body bytes, message-id de-duplication and idempotent redelivery.
- MCP tools (`list_pending`, `claim_conversation`, `get_history`, `send_reply` with 16 server-side guards, `finish_conversation`, `release_conversation`, `escalate_conversation`, `get_controls`, read-only `get_overview`) on a hand-written stateless MCP endpoint (no SDK), and an `/admin` staff console.
- Row-per-conversation store with per-row version guards and an atomic multi-row commit; daily retention pass; any conversation idle 180 days is dropped.
- Content-free, debounced wake POST with backoff and a daily Cron Trigger retry.
- Self-provisioning of secrets (`POST /api/setup`, once) and rotation through the admin token.
- `DELETE /api/admin/conversations/<id>` erases one conversation (also reachable as the admin action `delete_conversation`).
- `/api/admin/meta-setup` is off (404) unless `META_SETUP_ENABLED=1`.
- Deploy through `wrangler` (`scripts/deploy-cloudflare.sh`) or the Cloudflare API (`scripts/cf-api-deploy.mjs`), teardown script, offline and deployment smoke scripts, and `scripts/meta-setup.mjs` for Meta setup on your own computer.
- Documentation, hygiene scan with a self-test, issue forms, PR template, CI, PR-readiness and PR-title workflows, release-please configuration.
- README translations in 19 languages under `docs/readme/` (zh, zh-TW, ja, ko, tr, ru, vi, th, de, es, fr, uk, pl, pt-BR, ar, fa, id, it, el) with a language bar at the top of `README.md`; the English README stays authoritative. `npm run docs:check` verifies that each translation keeps the same code blocks, links and inline code as the English README, and that the language bars are complete. The docs link check now keeps combining marks when matching heading anchors, as GitHub does.
- **Admin MCP** at `/admin/mcp` (owner-only, stateless Streamable HTTP, zero runtime dependencies): `get_status`, `setup_check`, `list_conversations`, `get_conversation`, `erase_conversation`, `calling_status`, `arm_calling`, `disarm_calling`, `list_call_logs`, `get_call_log`, `get_usage_summary`, `get_version`, `check_for_update`. Disabled (404) unless the secret binding `ADMIN_MCP_TOKEN` (>= 32 chars) is set; constant-time token compare, Origin check, in-memory plus Durable Object rate limits, schema-validated arguments, redacted metadata-only results; no tool creates accounts or handles keys. The agent MCP at `/mcp` now shares the same JSON-RPC core. Docs: [docs/mcp.md](docs/mcp.md); threat model in `SECURITY.md`.
- **Voice calling (inbound, owner-gated, off by default)**: a clean port of a design first proven in a spike on 2026-10-17, then run live from this code the same day on Meta's test number (Meta SIP to xAI SIP, SDES, PCMA/PCMU, Grok Voice agent, the AI ends the call). `/api/xai-sip` webhook (Standard Webhooks signature), one `CallSession` Durable Object per call, `arm_calling`/`disarm_calling` windows (1-60 minutes, 1-5 calls) with last-call auto-disarm, a Durable Object dead-man alarm and a daily cron sweep, monthly call-seconds budget, per-call cap, caller allowlist, call log with text transcripts on by default (no audio). Owner gate: `CALLING_MODE` off/test/live, live needs `CALLING_BV_DONE=1` and `CALLING_GO_NUMBER`; no tool can change them. Cost note: about $0.08 per minute on the importer's own xAI account. Tested locally with fakes and run live on Meta's test number (calls answered, two-way, transcripts stored, the model's `end_call` handled and xAI's hang-up request accepted, gate arm and auto-disarm); not a business-verified production number. Evidence and limits: [docs/STATUS.md](docs/STATUS.md). Docs: [docs/VOICE-CALLS.md](docs/VOICE-CALLS.md). New Durable Object migration `v2` (`CallSession`); `scripts/cf-api-deploy.mjs deploy --migrate-from v1` for Workers created earlier.
- Non-affiliation notice (not affiliated with or endorsed by Meta or xAI; WhatsApp and Grok are trademarks of their owners) in the README, `DISCLAIMER.md` and every translation. The project keeps its name: both brand guidelines prohibit third-party product names containing WhatsApp or Grok.
- Setup docs: an assistant may drive the Meta developer-account setup, but the owner personally enters the SMS or voice code from their own SIM; it never reaches the assistant.
- **Voice call transcripts**: text only, on by default (`CALL_TRANSCRIPTS`; `0` turns them off), kept in the importer's own Durable Object for `CALL_TRANSCRIPT_RETENTION_DAYS` (default 30, 1 to 365) in a row separate from the call log. The session now asks xAI for caller transcription (`audio.input.transcription`, `grok-transcribe`): without it xAI sent no caller text, which is why the first live test call logged zero caller turns. `get_call_log` gains `include_transcript` (numbers and e-mail addresses masked unless `reveal_contact_details`, secrets scrubbed, labelled untrusted caller speech); new tool `erase_call_log` (14 tools). The agent no longer says the call is unrecorded and, if sincerely asked, says a transcript is kept. Audio recording was researched and is **not supported** (see `docs/VOICE-CALLS.md`). `docs/PRIVACY.md` and `SECURITY.md` carry the recording-consent note.
- AI disclosure stays **off by default** (`CALL_DISCLOSE_AI` is an owner option; the agent never claims to be human and answers truthfully if sincerely asked).
- Tests: 291 (229 logic, 62 workerd).

### Not included
- Outbound calls, SIP audio recording, voice providers other than xAI Grok Voice, preset routines, a settings page ([docs/ROADMAP.md](docs/ROADMAP.md)).
